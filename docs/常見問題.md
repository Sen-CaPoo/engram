# 常見問題

**目錄**：[產品](#產品) · [資料與隱私](#資料與隱私) · [使用](#使用) · [疑難排解](#疑難排解)

## 產品

### Engram 要付費嗎？

不用。Engram 以 [MIT 授權](../LICENSE)免費提供，可以自由使用於個人與商業用途。

### 支援哪些系統？

目前只支援 **Windows 11**。背景同步使用 Windows 工作排程器，安裝程式使用 winget 補齊工具。

### 需要什麼 Claude 方案？

只要能正常使用 Claude Code 即可。Engram 日常運作不呼叫 AI，不會額外消耗你的 Claude 額度；只有你主動輸入 `/engram` 指令、Claude Code 改版時的相容性探測（可關閉），以及你開啟自動駕駛時，才會使用你的額度。情境召回、護欄、環境健檢與自動更新都在你的電腦上計算，不用額度。

### Engram 和 Claude Code 內建的記憶有什麼不同？

Claude Code 的自動記憶只存在一台電腦、跟著資料夾路徑走。Engram 沿用同一套記憶格式，另外加上跨電腦同步、專案 ID、三種範圍、衝突處理、健康檢查與完整的復原能力。2.0 起，Engram 也照顧整個 Claude Code 環境：讓重要的記憶在對的時候出現、把踩過的坑變成護欄、檢查環境並讓幾台電腦共用同一套設定。Engram 不修改 Claude Code 本身，移除後 Claude Code 照常運作。

### 升級到 2.0 要注意什麼？

升級是免費的。更新方式和以前一樣（`git pull`、`engram update`）；升級後的第一次會發生的事，與各項功能的預設值，見[使用說明第 15 節](使用說明.md#15-更新)。1.x 沒有自動更新，所以還在 1.x 的每一台電腦，都要自己手動更新到 2.0.0 一次，更新到 2.0.0 之後的新版才會自動跟上。最重要的三件事：新的索引規則（糾正與偏好永遠列出、專案索引自動縮短、索引分層）要等所有電腦都更新到 2.0.0 之後才啟用，所以請讓每一台都更新；自動駕駛不再拆分或精簡記憶；從其他電腦同步來的環境設定、技能與護欄的「擋下」規則，要在每台電腦核可一次才會生效。

### 我只更新了一台，另一台還是舊版，會怎樣？

不會遺失資料，也不會壞掉，只是 2.0 的新索引規則暫時不生效：

- 共用的索引（全域的 `INDEX.md` 與每個專案的 `MEMORY.md`）會進入「相容模式」，維持舊的排法，兩台不會輪流改寫同一份索引。新的索引規則與索引分層要等所有電腦都更新之後才啟用。
- 舊版那台不會自動更新（1.x 沒有這個功能），要在那台手動 `git pull`、`engram update`。
- 混版期間，不要手動編輯記憶庫裡的 `settings.json`、`release.json`，以及 `env/`、`guardrails/`、`holding/` 底下的檔案：舊版不認得這些檔案，也不會替它們檢查疑似金鑰。
- 舊版更新到 2.0.0 之後，索引自動切換到新規則，你不用做任何事；超過 7 天沒有活動的舊版電腦不再算。`engram status` 會列出目前是不是相容模式、是哪幾台還是舊版。

詳見[使用說明第 15 節](使用說明.md#15-更新)。

### Engram 和 Anthropic 有關係嗎？

沒有。Engram 是獨立開發的第三方工具。Claude 與 Claude Code 是 Anthropic 的商標。

## 資料與隱私

### 記憶會被送到哪裡？

只會到**你自己的 GitHub 私人 repo** `engram-vault`（或你安裝時指定的 repo）。Engram 沒有伺服器，不蒐集任何資料。對話紀錄（transcript）不會同步；讀取統計只同步每筆記憶的讀取次數。完整的清單見下一題。

### 哪些資料會同步到我的私人記憶庫？哪些只留在這台電腦？

| 同步到你的私人記憶庫 | 只留在這台電腦 |
| --- | --- |
| 記憶檔、索引、核心準則，以及 Engram 的共用設定（例如索引分層） | 對話紀錄（Claude Code 自己存的，Engram 只在本機讀） |
| 每台電腦每筆記憶近 90 天的讀取次數、你確認過哪些內容版本的雜湊 | 對話回顧產生的保留區項目（裡面有對話原文），以及含疑似金鑰的保留區項目 |
| 環境指紋：只有名稱、版本與內容雜湊，沒有設定值 | 你糾正 Claude 的原話（同步的只有固定的分類與雜湊，不含原話；自動駕駛的提示詞只帶驗證過出自你的原話，不帶模型寫的主題） |
| 共用的環境設定檔與自製技能（會先過疑似金鑰檢查），以及各台電腦「這台略過」的清單 | 情境召回、護欄、搜尋的各種命中紀錄，與每週摘要 |
| 護欄規則 | 哪些環境設定、技能與護欄規則在這台核可過 |
| 沒有對話內容的保留區項目 | 環境設定套用前的備份、整理記錄、本機保管區（自動駕駛移出來的金鑰） |
| 發佈資訊（哪個版本、版本標籤指到哪裡；自動更新用） | 情境召回的索引（`~/.engram/local/cache/`） |
| 各台自動駕駛的狀態（開關、每個範圍整理到哪個版本）與你復原過的處理 | 自動駕駛每一輪的執行紀錄 |

含疑似金鑰的記憶檔不會被推送；環境設定檔、自製技能、護欄規則與保留區項目在寫進記憶庫之前就會先檢查，內容疑似含有金鑰的會被拒絕（保留區項目則改存在本機），不會進到會同步的地方。

### 環境健檢會讀我的設定值嗎？

幾乎不會。環境健檢只記名稱、版本、內容雜湊、數量與耗時：環境變數的值不讀，`settings.json` 只記有哪些鍵，設定值只記三樣（每個 hook 的指令開頭 80 個字，家目錄換成 `~`、疑似金鑰先遮蔽；哪些外掛是啟用的；對話紀錄的保留天數）；同步到記憶庫的環境指紋在寫入前還會過一次疑似金鑰偵測。為了統計 hook 的耗時與外掛的使用情形，它會在這台電腦掃描近 30 天的對話紀錄，只取統計數字，不記下、也不同步對話內容。不需要的話，到「設定 › 環境 › 環境健檢」關閉。

### 情境召回會不會把其他專案的記憶帶進這個對話？

不會。情境召回只從全域記憶、這台電腦的單機記憶與目前這個專案的記憶裡找，每次最多 3 筆；找的過程在你的電腦上完成，不呼叫 AI。想關掉，到「設定 › 情境召回與索引」（索引分層開啟時不能關）。想看其他專案的經驗，用 `/engram:recall`。

### 公司不允許把工作資料放在個人 GitHub 怎麼辦？

兩個選擇：

- 改用公司 GitHub 組織底下的私人 repo：請管理員建立一個空的 repo，安裝時加上 `--remote <repo 網址>`。
- 只在單機使用：安裝時加上 `--local`，記憶不離開這台電腦。

### Claude 寫了含密碼或金鑰的記憶怎麼辦？

那筆記憶不會被同步，收件匣會出現「疑似含有金鑰」卡片。按「移除金鑰」，再按「遮蔽並恢復同步」：記憶裡的值在本機換成「‹已遮蔽›」後才恢復同步。之後請改記「金鑰放在哪裡、怎麼取得」。核心準則也會要求 Claude 一開始就不要記下金鑰的值。偵測涵蓋常見格式（各家 API 金鑰與權杖、連線字串、私鑰、網址裡的帳密、`password: …` 這類寫法），但無法保證涵蓋所有寫法，請不要刻意把金鑰寫進記憶。

### 我的組織有開啟 Claude Code 遙測，會有影響嗎？

如果你的 Claude Code 帳號由組織管理並開啟了遙測（例如 OpenTelemetry），對話內容會依組織設定被記錄。Engram 不會改變這件事；但記憶的內容出現在對話中時，也會一併被記錄。

### 用 `/engram` 指令整理時，記憶會送給 AI 嗎？

會，和平常對話一樣送到 Claude，使用你的 Claude 額度。偵測到的疑似金鑰在送出前已在本機遮蔽。只有你輸入這些指令時，Claude 才會讀取記憶。

### 記憶整理會不會亂改我的記憶？

不會。`/engram:tidy` 只讀取記憶、建立整理記錄（技能只預先允許這些指令）：Claude 把建議與修改後的內容存成整理記錄，記憶本身不動。要等你在管理介面「記憶整理」逐項決定、把 `/engram:tidy-apply` 貼回 Claude Code，才會執行；採用建議的項目照你在網頁上看過的內容寫入，不會重新生成。執行前會先備份，建議之後被改過的記憶不會被覆蓋，每一項都可以在結果頁復原。

### 對話回顧會把對話紀錄送出去嗎？

對話紀錄不會同步，也不會上傳到 GitHub。輸入 `/engram:dream` 時，Engram 在這台電腦把還沒回顧的對話轉成精簡的文字（疑似金鑰先遮蔽），放在 `~/.engram/local/dream/`，由你的 Claude Code 讀取分析，和平常對話一樣使用你的 Claude 額度；這些文字在整理記錄建立後就刪除，中途沒完成的 14 天後自動清除。分析時不會改動任何記憶，建議要等你在記憶整理頁決定後才執行。

### 對話回顧要花多少額度？

每一份對話文字（很長的對話會切成幾份）由一個分析用的子代理（Sonnet）讀完，所以用量和對話的長度、數量成正比。預設一次回顧 20 個對話（`--sessions` 可調整，上限 100）；對話很多或很長時，可以用 `/engram:dream --sessions 5` 先回顧最舊的幾個，其餘留到下次。

### 自動駕駛會不會改壞我的記憶？

自動駕駛不需要你逐項確認，所以改用程式與第二次 AI 審核把關：AI 只回傳決定、不能直接寫檔；改寫、合併、封存與寫進每次都會載入的範圍都要審核員同意；看起來像被注入的指示一定送審；對話回顧寫進全域或單機的內容要有你自己說過的話當證據；每輪最多改 30 筆記憶，只封存不刪除。2.0 起也不會拆分記憶，不為了縮短而刪減內文（改寫後大幅變短的一定送審核員）。每一項執行前都會備份，事後在「自動駕駛」頁可以逐項或整輪復原；同一類處理在兩輪各被你復原過就會自動暫停，之後可以一鍵恢復。審核員沒有放行的建議不會消失，會存進「保留區」讓你決定（見下方「保留區是什麼」）。

### 自動駕駛要花多少額度？會送出什麼？

它用你電腦上的 Claude Code 登入呼叫 Claude，送出的是要判斷的記憶與對話文字（疑似金鑰先在本機遮蔽），和你自己輸入 `/engram:tidy`、`/engram:dream` 一樣；不載入你的 CLAUDE.md 與設定，也不留對話紀錄。用訂閱時不另外計費，但會消耗額度：每台每月上限預設約當 US$200 的 API 牌價（在「自動駕駛」頁可以選常用金額或自訂 1～1000，也可以執行 `engram autopilot budget <美元>`）。沒有每輪的金額上限，一輪可以用到本月剩下的全部；本月用完或碰到 Claude 的用量上限就停止。只在電腦閒置 20 分鐘以上時執行，避免和你搶額度。

### 兩台電腦都開自動駕駛，會不會互相改？

1.6.0 起每台電腦平等，都會整理共用的記憶（全域、核心準則、專案記憶）與處理同步衝突。每一輪開始前先同步拿到另一台的變更；每個範圍整理到哪個版本會記在記憶庫裡跟著同步，另一台整理過、內容也沒再變的範圍就跳過，所以不會重複整理、也不會兩台輪流改同一批。萬一兩台剛好同時改到同一筆，同步時會變成衝突，下一輪再合併，兩邊的內容都不會遺失。單機記憶只由自己那台整理。請讓每台電腦都用同一個版本：版本太舊的電腦看不到其他電腦的整理紀錄，可能重複整理。

### 自動駕駛把金鑰移到哪裡了？

移到這台電腦的本機保管區 `~/.engram/local/secrets/`，用 Windows DPAPI 加密，只有這台電腦的這個使用者解得開，不會同步。記憶裡原本的值換成 `<engram-secret:名稱>`，結尾附上取出的指令，用 `engram secret get <名稱>` 取出、`engram secret list` 列出。重灌 Windows 之後舊的值會解不開（加密綁在這台電腦的這個使用者）：`engram secret check` 會列出哪幾筆解不開，確定找不回的用 `engram secret delete <名稱>` 移除；在那之前對話回顧會暫停匯出，避免值外流。

### 收件匣為什麼出現「待你確認」？

Claude 自己寫入了全域記憶、單機記憶或核心準則。這些內容每次對話都會載入、影響每個專案，所以請你看一下差異，確認、編輯或退回。你在管理介面改的、在記憶整理頁採用建議的、用 `/engram:save` 同意寫入的不會再問；選「依備註調整」由 Claude 改寫的內容仍會請你確認。不需要時可以在設定頁關閉。注意：「不會再問」不等於「是你的偏好」，見下方「為什麼我存的偏好，自動駕駛沒有遵守」。

### 讀取統計是怎麼算的？

Engram 從這台電腦的對話紀錄找出 Claude 讀了哪些記憶（用 Read 讀檔、`engram memory show`、在終端機讀檔），同一個對話同一天讀同一筆只算一次。統計在本機計算，不用到 Claude 額度；每天把近 90 天的讀取次數同步一次，兩台電腦的次數會合計。

### 記憶面板會把記憶送出去嗎？

不會。記憶面板只在你的電腦上讀取檔案、整理成清單，不呼叫 AI、不用到額度，也不連線到任何地方。

## 使用

### 兩台電腦同時開著會怎樣？

沒有問題。兩邊各自存檔、各自同步，改到不同記憶時會自動合併；改到同一筆的同一段才會出現衝突卡。

### 公司網路擋住 GitHub 怎麼辦？

記憶照樣存在本機，狀態顯示「離線」，回到可以連 GitHub 的網路後會自動補同步。如果是公司代理或 TLS 檢查造成的，`engram sync` 的錯誤訊息會告訴你要設定什麼，例如 `git config --global http.sslBackend schannel`。

### 換新電腦或重灌之後？

照[快速開始](快速開始.md)安裝即可，新電腦會自動接上記憶庫。新電腦會有新的身分；舊電腦的單機記憶仍保存在記憶庫裡，可以在「記憶庫」頁搬到新電腦的單機範圍。

### 原本 `~/.claude/CLAUDE.md` 裡的工作準則會被搬走嗎？

不會。安裝只在檔案末尾加一段兩行的區塊。如果希望每台電腦的工作準則一致：在「匯入既有記憶」頁套用匯入之後，按「同步工作準則」，先預覽搬移後的內容，同意後才搬進記憶庫，之後也能逐位元還原。

### 對話中切換權限模式，記憶還讀得到嗎？

從專案根目錄開啟的對話可以，任何模式都不會跳出詢問。從子資料夾開啟時，記憶要經由連結讀寫，切到 acceptEdits 或 default 模式會跳出詢問；這種情況對話開頭會提醒你，建議改從專案根目錄開啟。

### 記憶太多會不會拖慢 Claude？

Claude 每次只先讀一份很短的索引，內文等需要時才讀。Engram 會控制全域與單機索引的長度，放不下時釘選的與你的糾正、偏好永遠留在索引裡；超出的記憶仍然可以用 `engram search` 找到，也可能被情境召回在相關的時候帶出。專案索引到載入上限的 80% 時，Engram 會自動把每一行縮短，仍放不下才依重要性省略（並註明「另有 N 筆未列出」）。這兩項新規則要等所有電腦都更新到 2.0.0 之後才生效。

### 怎麼知道 Claude 這次讀了哪些記憶？

打開記憶面板：點 Claude Code 底部的「◆ 憶跡」，或輸入 `/engram-memories`。面板分成「開場載入」與「對話中讀取」，每一列標出 Claude 看到的是全文、只有標題，還是搜尋摘要。開場載入的索引只讓 Claude 知道有哪些記憶；某一則的內容要等 Claude 讀取後，才會出現在「對話中讀取」。詳見[使用說明第 4 節](使用說明.md#4-記憶面板這次對話讀了哪些記憶)。

### 為什麼建議把 Claude Code 的預設權限模式設為 auto？

不設也能用：從專案根目錄開 Claude Code 完全正常。設為 auto（或 bypassPermissions）時，Engram 會另外建立記憶連結，讓「從子資料夾開啟」也能讀寫同一套記憶。

### 為什麼我存的偏好，自動駕駛沒有遵守？

自動駕駛只遵守**你本人確認過**的偏好，加上安裝時既有的內容。它看的是核心準則，以及全域的「回饋」與「使用者」記憶。在 Claude Code 的對話裡做的寫入（包含 `/engram:save`、`/engram:tidy-apply`、`/engram:inbox` 處理衝突，以及對話裡執行的 `engram remember --reviewed`、`engram holding adopt`、`engram import apply`）一律記成「Claude 代為確認」，加上自動駕駛代你確認的內容，都不會自動變成它的規則：對話裡寫入的內容可能被夾帶的指示誘導，所以要你自己點頭。同一個指令在你自己開的終端機（不是 Claude Code 的對話）執行，才算你本人確認。

怎麼讓它生效：打開管理介面的「自動駕駛」頁，在「自動駕駛遵守的偏好」的「還沒採用」找到那一筆，按「這是我的偏好」（有好幾筆時可以「全部確認」）。「判斷時會遵守」那一份列出它現在遵守的全部內容。也可以在你自己的終端機執行 `engram autopilot preferences`。如果某一筆標示「這次沒有帶給自動駕駛」，是偏好太多、超過字數上限，精簡一下內容即可。同一個區塊還有一份「候選」：常被使用、但還沒由你本人確認的其他記憶（例如全域的參考類記憶、這台的單機記憶）；確認它們不會變成自動駕駛遵守的偏好，是讓記憶畢業之後可以把它們寫進核心準則或變成護欄規則。

### 保留區是什麼？要不要處理？

保留區放的是自動駕駛想做、但沒有執行的建議：審核員沒有放行、這一輪處理不了的範圍，或被退回的版本。內容與證據都完整保存。你不需要特地清空它：保留區不是記憶，不會出現在索引或搜尋裡，也不影響 Claude 讀到什麼。想看的時候到管理介面的「保留區」頁（或 `engram holding`），看過之後可以「採用」（寫進記憶，先備份、可以復原）或標成「不需要」（90 天內同一個提案不會再送審）。審核員沒有放行、或這一輪處理不了的項目，自動駕駛之後的幾輪也會自己再審，最多兩次（從其他電腦同步來的項目，這台不會重審，留給你決定）。已處理超過 90 天的項目會自動清掉。

### 護欄擋下了我要執行的指令，怎麼辦？

1. **先看說明。** Claude 會收到一則以「[Engram 護欄]」（英文是「[Engram guardrail]」，語言依序看記憶面板選過的語言、Claude Code 的 `language` 設定、系統語系，都沒有時用英文）開頭的訊息，說明這個寫法為什麼會出錯，以及正確的寫法。通常 Claude 自己就會改寫後重送。
2. **確定擋錯了**：請 Claude 把同一個指令原封不動再送一次，同一場對話裡會放行。重送成功時，Engram 會把這條規則在這台電腦降成「只提醒」，14 天後自動恢復。（有一類規則防的是「悄悄出錯、不會報錯」的問題，重送成功不代表擋錯，所以不會自動降級，要不要調整由你決定。）
3. **不想再被這條擋下**：到「環境 › 護欄」，在這台電腦停用那一條規則（不影響其他電腦）；或到「設定 › 護欄」改成「只提醒」或「關閉」。
4. **想確認是哪一條**：「環境 › 護欄」的「試試看」，貼上指令就會列出命中的規則（只比對、不會執行）。

護欄壞掉或超時，指令照常送出，不會卡住你。

### 同步來的設定，為什麼要我核可？

環境設定、自製技能與護欄的「擋下」規則，套用之後會在這台電腦直接生效，不會再問你。所以從其他電腦同步來的內容，一定要你在這台看過完整內容、按「核可」才會套用；內容之後又被改過，要重新核可。核可只能在管理介面（「環境 › 設定同步」、「環境 › 護欄」）或你自己的終端機（`engram env approve`、`engram guardrails approve <規則 id>`）做；在 Claude Code 的對話裡執行會被拒絕，這樣 AI 就不能替你核可、再自己套用。沒核可的設定只會列在「等待這台核可」，不會被套用。

### 自動更新會不會把壞掉的版本裝上來？怎麼關掉？

自動更新每一步都有把關：只接受你安裝用的那個儲存庫、帶版本標籤、標籤指到的就是發佈的那一版；這台的 Engram 資料夾必須是乾淨的 git 複本，而且只接受「往前推進」的更新。更新前先備份，更新後跑一次檢查並確認新版常駐程式起得來；任何一步失敗就自動退回原本的版本並通知你，同一個發佈不會再重試。用 ZIP 安裝（不是 git 複本）或開發用的安裝，不會自動更新。

要關掉：到管理介面「設定 › 自動更新」把開關關閉；之後照舊用 `git pull` 與 `engram update` 手動更新。想知道這台為什麼沒有更新，看同一區的「上次檢查」，會寫出原因。

### 我的專案怎麼不見了？

可能是休眠了。一個專案在所有電腦都沒有綁定資料夾、而且最近 90 天沒有任何對話跡象，就會休眠：「專案」頁預設只顯示「使用中」的專案，休眠的在「休眠」分頁；自動駕駛與整理類的檢查不再處理它。記憶完整保留、照常搜尋，重新在那個專案的資料夾開 Claude Code 就會自動恢復。

### 收件匣說兩個專案可能是同一個，要合併嗎？

確定是同一個專案才合併。判斷依據會寫在卡片上：git 遠端完全相同時最可能是同一個專案；只有部分遠端或根 commit 相同時，很可能是 fork 或同一個樣板，不是同一個專案。合併會把一個專案的記憶搬進另一個，可以在「裝置與同步」的變更紀錄還原，但還原只復原記憶庫與這台電腦的綁定，其他電腦要自己檢查。自動駕駛不處理這種建議，只留給你決定。

## 疑難排解

先執行 `engram doctor`：它會逐項檢查 git、合併設定、每個專案的連結、遠端連線、常駐程式與登入工作。

| 狀況 | 先試試 |
| --- | --- |
| `setup.cmd` 說找不到 winget | 到 Microsoft Store 更新「應用程式安裝程式」，或手動安裝畫面上列出的工具後，再執行一次 `setup.cmd` |
| 工具裝完後仍說找不到 | 關閉視窗，再雙擊一次 `setup.cmd`。新安裝的程式要等新開的視窗才讀得到 |
| 「Node.js 版本太舊」 | 執行 `winget upgrade --id OpenJS.NodeJS.LTS`，關閉視窗後再執行一次 `setup.cmd` |
| 「無法執行 Claude Code」 | Claude Code 不在 PATH 上，或是用 npm 安裝的（claude.cmd）。在 PowerShell 執行 `irm https://claude.ai/install.ps1 \| iex` 改用官方安裝程式，開新視窗後再安裝 Engram |
| 「需要已登入的 GitHub CLI」 | 執行 `gh auth login` 登入後重試；或用 `--remote` 指定記憶庫、`--local` 只在這台電腦使用 |
| 「連接埠 4777 已被其他程式占用」 | 關閉占用 4777 的程式後執行 `engram ui`。管理介面的網址固定，不能換連接埠 |
| 終端機找不到 `engram` | 開一個新的終端機視窗。還是不行的話，在 PowerShell 改用 `node "$HOME/.engram/app/current/bin/engram.mjs" status` |
| 另一台的記憶沒有出現 | 兩台都執行 `engram sync`，再看 `engram status` 的同步狀態 |
| 需要重新登入 GitHub | 在終端機執行 `gh auth login` 重新登入；如果 git 的認證沒有交給 GitHub CLI，在 PowerShell 執行 `git -C "$HOME/.engram/vault" fetch`，跳出瀏覽器後登入 |
| 讀寫記憶時一直跳出權限詢問 | 先確認是從專案根目錄開啟 Claude Code。收件匣如果有「讀取記憶時會跳出權限詢問」卡片，按「允許讀取」；有「讀寫記憶時會跳出權限詢問」卡片，按「改用設定檔連結」 |
| 看不到 `/engram:inbox` 等指令 | 在已開的對話執行 `/reload-plugins`，或開一個新對話 |
| 看不到記憶面板或底部的「◆ 憶跡」 | 輸入 `/engram-memories` 開啟（自動開啟只在全螢幕版面、終端機至少 144 欄寬時）。剛更新 Engram 的話，在已開的對話執行 `/reload-plugins`。還是沒有的話執行 `claude update`：面板需要支援外掛畫面的 Claude Code（實測 2.1.329、2.1.330，更早的版本沒有測試） |
| 情境召回沒有帶出記憶，或護欄沒有擋下指令 | 兩者都靠外掛的 mod 運作。先在已開的對話執行 `/reload-plugins`；Claude Code 不支援外掛畫面時，情境召回改由後備的指令型 hook 接手（效果一樣），但護欄沒辦法擋下指令，只在對話開頭列出提醒。也確認設定頁的「情境召回」「護欄」沒有被關閉 |
| 自動更新沒有更新 | 「設定 › 自動更新」的「上次檢查」會寫出原因。常見的有：用 ZIP 安裝（不是 git 複本）、Engram 資料夾有未提交的修改、有對話進行中（稍後再試）、這台已經是最新版 |
| 「環境 › 兩台差異」說還沒有可以比較的電腦 | 要兩台以上的電腦都更新到 2.0.0，而且各自完成一次環境檢查（每天 10:00 自動做，或執行 `engram env`） |
| 同步卡住，收到「同步已連續失敗」的通知 | 打開管理介面「裝置與同步」看原因。Engram 會自己診斷：被扣住（疑似金鑰）的檔案擋住合併時，先備份、暫時移開、合併後放回原位，另一台的版本存進衝突區，不會丟掉你這台的版本。看到疑似金鑰的卡片時，照卡片遮蔽或移除金鑰即可恢復 |
| `engram status` 說索引是相容模式 | 記憶庫裡還有近 7 天內用過、版本低於 2.0.0 的電腦（狀態會列出是哪幾台）。把那幾台更新到 2.0.0（`git pull`、`engram update`），索引會自動切換，不用做別的事。已經不用的舊電腦，超過 7 天沒有活動就不再算 |
| 自動駕駛停下來了 | 「自動駕駛」頁上方會寫原因：用量上限（會自動繼續）、Claude Code 的登入到期（在終端機執行 `claude auth login`，或在 Claude Code 輸入 `/login`），或 Claude 暫時忙碌（會自動再試） |
| 點底部的「◆ 憶跡」沒有反應 | Claude Code 在一般畫面（設了 `CLAUDE_CODE_NO_FLICKER=0`，或在 tmux 裡執行）收不到滑鼠點擊。改用 `/engram-memories`；或拿掉這個環境變數、不在 tmux 裡執行，回到預設的全螢幕版面 |
| 想看詳細紀錄 | `%USERPROFILE%\.engram\local\logs\`（可以直接貼到檔案總管的網址列） |

還是解決不了？請到 [GitHub Issues](https://github.com/Sen-CaPoo/engram/issues) 回報，附上 `engram doctor` 的結果（貼上前請確認沒有個人資料）。
