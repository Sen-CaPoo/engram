# 常見問題

**目錄**：[產品](#產品) · [資料與隱私](#資料與隱私) · [使用](#使用) · [疑難排解](#疑難排解)

## 產品

### Engram 要付費嗎？

不用。Engram 以 [MIT 授權](../LICENSE)免費提供，可以自由使用於個人與商業用途。

### 支援哪些系統？

目前只支援 **Windows 11**。背景同步使用 Windows 工作排程器，安裝程式使用 winget 補齊工具。

### 需要什麼 Claude 方案？

只要能正常使用 Claude Code 即可。Engram 日常運作不呼叫 AI，不會額外消耗你的 Claude 額度；只有你主動輸入 `/engram` 指令，或 Claude Code 改版時的相容性探測（可關閉），才會使用你的額度。

### Engram 和 Claude Code 內建的記憶有什麼不同？

Claude Code 的自動記憶只存在一台電腦、跟著資料夾路徑走。Engram 沿用同一套記憶格式，另外加上跨電腦同步、專案 ID、三種範圍、衝突處理、健康檢查與完整的復原能力。Engram 不修改 Claude Code 本身，移除後 Claude Code 照常運作。

### Engram 和 Anthropic 有關係嗎？

沒有。Engram 是獨立開發的第三方工具。Claude 與 Claude Code 是 Anthropic 的商標。

## 資料與隱私

### 記憶會被送到哪裡？

只會到**你自己的 GitHub 私人 repo** `engram-vault`（或你安裝時指定的 repo）。Engram 沒有伺服器，不蒐集任何資料。對話紀錄（transcript）不會同步。

### 公司不允許把工作資料放在個人 GitHub 怎麼辦？

兩個選擇：

- 改用公司 GitHub 組織底下的私人 repo：請管理員建立一個空的 repo，安裝時加上 `--remote <repo 網址>`。
- 只在單機使用：安裝時加上 `--local`，記憶不離開這台電腦。

### Claude 寫了含密碼或金鑰的記憶怎麼辦？

那筆記憶不會被同步，收件匣會出現「疑似含有金鑰」卡片。按「移除金鑰」，再按「遮蔽並恢復同步」：記憶裡的值在本機換成「‹已遮蔽›」後才恢復同步。之後請改記「金鑰放在哪裡、怎麼取得」。核心準則也會要求 Claude 一開始就不要記下金鑰的值。偵測涵蓋常見格式（各家 API 金鑰與權杖、連線字串、私鑰、網址裡的帳密、`password: …` 這類寫法），但無法保證涵蓋所有寫法，請不要刻意把金鑰寫進記憶。

### 我的組織有開啟 Claude Code 遙測，會有影響嗎？

如果你的 Claude Code 帳號由組織管理並開啟了遙測（例如 OpenTelemetry），對話內容會依組織設定被記錄。Engram 不會改變這件事；但記憶的內容出現在對話中時，也會一併被記錄。

### 用 `/engram` 指令整理時，記憶會送給 AI 嗎？

會，和平常對話一樣送到 Claude，使用你的 Claude 額度。偵測到的疑似金鑰在送出前已在本機遮蔽。只有你輸入這些指令時，Claude 才會讀取記憶。

### 記憶整理會不會亂改我的記憶？

不會。`/engram:tidy` 只讀取記憶、建立整理記錄（技能只預先允許這些指令）：Claude 把建議與修改後的內容存成整理記錄，記憶本身不動。要等你在管理介面「記憶整理」逐項決定、把 `/engram:tidy-apply` 貼回 Claude Code，才會執行；採用建議的項目照你在網頁上看過的內容寫入，不會重新生成。執行前會先備份，建議之後被改過的記憶不會被覆蓋，每一項都可以在結果頁復原。

### 記憶面板會把記憶送出去嗎？

不會。記憶面板只在你的電腦上讀取檔案、整理成清單，不呼叫 AI、不用到額度，也不連線到任何地方。

## 使用

### 兩台電腦同時開著會怎樣？

沒有問題。兩邊各自存檔、各自同步，改到不同記憶時會自動合併；改到同一筆的同一段才會出現衝突卡。

### 公司網路擋住 GitHub 怎麼辦？

記憶照樣存在本機，狀態顯示「離線」，回到可以連 GitHub 的網路後會自動補同步。如果是公司代理或 TLS 檢查造成的，`engram sync` 的錯誤訊息會告訴你要設定什麼，例如 `git config --global http.sslBackend schannel`。

### 換新電腦或重灌之後？

照[快速開始](快速開始.md)安裝即可，新電腦會自動接上記憶庫。新電腦會有新的身分；舊電腦的單機記憶仍保存在記憶庫裡，可以在「記憶庫」頁搬到新電腦的單機範圍。

### 原本 `~/.claude/CLAUDE.md` 裡的工作準則會被搬走嗎？

不會。安裝只在檔案末尾加一段兩行的區塊。如果希望每台電腦的工作準則一致：在「匯入既有記憶」頁套用匯入之後，按「同步工作準則」，先預覽搬移後的內容，同意後才搬進記憶庫，之後也能逐位元還原。

### 對話中切換權限模式，記憶還讀得到嗎？

從專案根目錄開啟的對話可以，任何模式都不會跳出詢問。從子資料夾開啟時，記憶要經由連結讀寫，切到 acceptEdits 或 default 模式會跳出詢問；這種情況對話開頭會提醒你，建議改從專案根目錄開啟。

### 記憶太多會不會拖慢 Claude？

Claude 每次只先讀一份很短的索引，內文等需要時才讀。Engram 會控制全域與單機索引的長度，超出的記憶仍然可以用 `engram search` 找到。專案索引接近 200 行上限時，收件匣會提醒你整理。

### 怎麼知道 Claude 這次讀了哪些記憶？

打開記憶面板：點 Claude Code 底部的「◆ 憶跡」，或輸入 `/engram-memories`。面板分成「開場載入」與「對話中讀取」，每一列標出 Claude 看到的是全文、只有標題，還是搜尋摘要。開場載入的索引只讓 Claude 知道有哪些記憶；某一則的內容要等 Claude 讀取後，才會出現在「對話中讀取」。詳見[使用說明第 4 節](使用說明.md#4-記憶面板這次對話讀了哪些記憶)。

### 為什麼建議把 Claude Code 的預設權限模式設為 auto？

不設也能用：從專案根目錄開 Claude Code 完全正常。設為 auto（或 bypassPermissions）時，Engram 會另外建立記憶連結，讓「從子資料夾開啟」也能讀寫同一套記憶。

## 疑難排解

先執行 `engram doctor`：它會逐項檢查 git、合併設定、每個專案的連結、遠端連線、常駐程式與登入工作。

| 狀況 | 先試試 |
| --- | --- |
| `setup.cmd` 說找不到 winget | 到 Microsoft Store 更新「應用程式安裝程式」，或手動安裝畫面上列出的工具後，再執行一次 `setup.cmd` |
| 工具裝完後仍說找不到 | 關閉視窗，再雙擊一次 `setup.cmd`。新安裝的程式要等新開的視窗才讀得到 |
| 「Node.js 版本太舊」 | 執行 `winget upgrade --id OpenJS.NodeJS.LTS`，關閉視窗後再執行一次 `setup.cmd` |
| 「無法執行 Claude Code」 | Claude Code 不在 PATH 上，或是用 npm 安裝的（claude.cmd）。在 PowerShell 執行 `irm https://claude.ai/install.ps1 \| iex` 改用官方安裝程式，開新視窗後再安裝 Engram |
| 「需要已登入的 GitHub CLI」 | 執行 `gh auth login` 登入後重試；或用 `--remote` 指定記憶庫、`--local` 只在這台電腦使用 |
| 「連接埠 4777 已被其他程式占用」 | 關閉占用 4777 的程式後執行 `engram ui`。管理介面的網址固定，不能換連接埠 |
| 終端機找不到 `engram` | 開一個新的終端機視窗。還是不行的話，在 PowerShell 改用 `node "$HOME/.engram/app/current/bin/engram.mjs" status` |
| 另一台的記憶沒有出現 | 兩台都執行 `engram sync`，再看 `engram status` 的同步狀態 |
| 需要重新登入 GitHub | 在終端機執行 `gh auth login` 重新登入；如果 git 的認證沒有交給 GitHub CLI，在 PowerShell 執行 `git -C "$HOME/.engram/vault" fetch`，跳出瀏覽器後登入 |
| 讀寫記憶時一直跳出權限詢問 | 先確認是從專案根目錄開啟 Claude Code。收件匣如果有「讀取記憶時會跳出權限詢問」卡片，按「允許讀取」；有「讀寫記憶時會跳出權限詢問」卡片，按「改用設定檔連結」 |
| 看不到 `/engram:inbox` 等指令 | 在已開的對話執行 `/reload-plugins`，或開一個新對話 |
| 看不到記憶面板或底部的「◆ 憶跡」 | 輸入 `/engram-memories` 開啟（自動開啟只在全螢幕版面、終端機至少 144 欄寬時）。剛更新 Engram 的話，在已開的對話執行 `/reload-plugins`。還是沒有的話執行 `claude update`：面板需要支援外掛畫面的 Claude Code（實測 2.1.307 至 2.1.309） |
| 點底部的「◆ 憶跡」沒有反應 | Claude Code 在一般畫面（設了 `CLAUDE_CODE_NO_FLICKER=0`，或在 tmux 裡執行）收不到滑鼠點擊。改用 `/engram-memories`；或拿掉這個環境變數、不在 tmux 裡執行，回到預設的全螢幕版面 |
| 想看詳細紀錄 | `%USERPROFILE%\.engram\local\logs\`（可以直接貼到檔案總管的網址列） |

還是解決不了？請到 [GitHub Issues](https://github.com/Sen-CaPoo/engram/issues) 回報，附上 `engram doctor` 的結果（貼上前請確認沒有個人資料）。
