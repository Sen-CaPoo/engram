# 使用說明

Engram 安裝好之後幾乎不需要操作。這份說明介紹日常會用到的功能，以及需要你決定時該怎麼做。還沒安裝的話，先看[快速開始](快速開始.md)。

## 1. 運作方式

<p align="center">
  <img src="assets/illustrations/how-it-works.webp" alt="公司電腦、家裡電腦、筆電都透過背景同步，連到你的 GitHub 私人 repo engram-vault" width="800">
</p>

| 概念 | 說明 |
| --- | --- |
| 記憶庫（vault） | 所有記憶集中在 `%USERPROFILE%\.engram\vault`，它是一個 git repo，同步到你 GitHub 上的私人 repo `engram-vault` |
| 三種範圍 | **全域**：所有專案都成立，例如你的偏好。**專案**：只屬於某個專案，例如部署方式。**單機**：只在這台電腦成立，例如安裝路徑、網路設定 |
| 專案 ID | 每個專案有固定的 ID。git 專案用 remote 認，其他資料夾用標記檔認，所以搬家、改名、換電腦都認得 |
| 綁定 | 把專案資料夾接到記憶庫裡對應的位置。git 專案在另一台電腦第一次開 Claude Code 時自動綁定 |

Engram 不修改 Claude Code 本身，只使用官方的記憶資料夾、`CLAUDE.md` 匯入、hooks，以及外掛畫面（記憶面板）。

三種範圍怎麼分？判斷原則只有一句：**換到另一台電腦還成立嗎？** 不成立的放「單機」；成立的話再問**換到別的專案還成立嗎？** 成立的放「全域」，不成立的放「專案」。

<p align="center">
  <img src="assets/illustrations/scopes.webp" alt="全域：每個專案都看得到；專案：只屬於這個專案；單機：只在這台電腦成立" width="800">
</p>

## 2. 平常怎麼用

什麼都不用做。Claude 照平常記憶事情，Engram 在背景處理其他的事：

| 時機 | Engram 做什麼 |
| --- | --- |
| 對話開始 | 帶入狀態：Claude 知道自己在哪台電腦、哪個專案，也知道全域與單機記憶要寫到哪裡 |
| 對話中 | 專案記憶照官方方式寫；全域與單機記憶由 Claude 用 `engram remember` 寫入，寫完會告訴你 |
| 對話結束 | 整理索引、檢查有沒有疑似金鑰，然後存進記憶庫 |
| 每 10 分鐘（預設） | 和其他電腦交換變更。離線時先存在本機，恢復連線後自動補上。間隔可在設定頁調整 |
| 每天一次（預設 09:30） | 健康檢查（同時從這台電腦的對話紀錄更新讀取統計），有需要你決定的事就放進收件匣 |

想主動整理時：

- 管理介面的「記憶庫」可以搜尋、編輯，或用「改變範圍」把記憶移到全域、單機或別的專案。重複的記憶會出現在收件匣的「內容相同的記憶」或「可能重複」卡片，在那裡合併。
- 「專案」頁可以看到每個專案的記憶索引（MEMORY.md）離 Claude Code 的載入上限還有多少。
- 「總覽」的「最近一次對話載入了什麼」列出 Claude 實際讀進了哪些檔案、各有多大。想在對話當下看，用 Claude Code 裡的記憶面板（第 4 節）。

## 3. 在 Claude Code 裡用 AI 整理

健康檢查只用規則判斷，只能找出「名稱相同」「檔案太大」這類候選；要不要升級全域、是不是真的重複、還有沒有用，要讀過內容才知道。這些判斷交給你自己的 Claude Code：

| 指令 | 做什麼 | 管理介面的入口 |
| --- | --- | --- |
| `/engram:inbox` | 逐張讀過收件匣的卡片，說明判斷依據與建議，你同意後才執行。加上卡片 id 只處理那一張；加上「自動」會直接處理有把握的項目，同步衝突、疑似金鑰、資料夾綁定與改名、大量刪除、封存與沒把握的項目仍留給你決定 | 收件匣頁首「交給 Claude 整理」、卡片上的「交給 Claude」、衝突卡的「交給 Claude 合併」 |
| `/engram:tidy` | 深度整理全域、單機、一個專案、核心準則、全部範圍或單筆記憶：找出語意重複、過時、互相矛盾、放錯範圍、說明不清楚的記憶，把建議（含修改後的完整內容）存成整理記錄，給你網址到管理介面逐項決定。分析時不改任何記憶（見下方「記憶整理」） | 「記憶整理」頁產生指令；專案頁「請 Claude 整理」、記憶庫「請 Claude 檢查」、核心準則頁「請 Claude 精簡」會帶著範圍開啟這一頁 |
| `/engram:tidy-apply` | 照你在記憶整理頁的決定執行：採用建議的項目照你看過的內容寫入，依備註調整的項目由 Claude 依備註處理，最後回報結果與復原方式 | 記憶整理頁的「產生執行指令」 |
| `/engram:dream` | 對話回顧：拿這台電腦最近的對話紀錄當證據，逐筆驗證一個專案的記憶，並補上漏記的事；建議同樣存成整理記錄，由你逐項決定（見下方「對話回顧」） | 「記憶整理」頁選專案、整理方式選「對照對話紀錄」；專案頁「回顧對話」；收件匣的「建議回顧」卡片 |
| `/engram:save` | 回顧這次對話，把值得長期記住的事存成記憶：判斷範圍、先查有沒有相近的記憶，有就更新那一筆 | 在對話中使用 |
| `/engram:autopilot` | 自動駕駛：開啟或關閉、立即執行一輪、看某一輪做了什麼、復原（見下方「自動駕駛」） | 「自動駕駛」頁、設定頁 |
| `/engram:recall` | 從其他專案、全域與每台電腦的記憶找出相關經驗，整理成可以直接套用的結論並附來源；只讀不寫 | 在對話中使用 |

### 記憶整理：Claude 提建議，你逐項決定

<p align="center">
  <img src="assets/screenshots/tidy.png" alt="記憶整理頁：上方是 Claude 的整體結論與進度，下方每一項有建議、理由、差異比對與「採用建議／維持原狀／封存／依備註調整」" width="900">
</p>

1. **選範圍**：在管理介面打開「記憶整理」，選全域、單機（這台）、專案、核心準則或全部記憶，需要的話寫補充說明（例如「重點看重複」「客戶相關的先不要動」），按「複製指令」。
2. **交給 Claude 分析**：在 Claude Code 貼上 `/engram:tidy …`。Claude 讀過記憶，把每一項的建議、理由與修改後的完整內容存成整理記錄，最後給你一個回到管理介面的網址。這一步不改任何記憶。
3. **逐項決定**：每一項可以看 Claude 的建議與理由、「看差異」比對修改前後、展開「目前內容」，然後選：

   | 決定 | 會怎麼做 |
   | --- | --- |
   | 採用建議 | 照你看到的內容執行（改寫、搬移、合併、新增、封存） |
   | 維持原狀 | 不動 |
   | 封存 | 移到歷史，之後可以還原 |
   | 依備註調整 | 在備註寫下要怎麼改，由 Claude 依備註處理 |

   決定會自動儲存，可以分幾次做完。「未決定的照建議」一次把剩下的照 Claude 的建議處理。建議之後記憶被改過（例如另一台電腦同步過來）的項目會標出來；執行時那一項不會寫入（標成失敗），不會覆蓋。
4. **執行**：按「產生執行指令」，把 `/engram:tidy-apply <id>` 貼回 Claude Code。Engram 先把會動到的檔案備份到 `~/.engram/local/backups/`，採用建議的項目照內容執行，依備註調整的交給 Claude；一項失敗不影響其他項。結果回到同一頁，每一項都有「復原這一項」。

<p align="center">
  <img src="assets/screenshots/tidy-start.png" alt="記憶整理首頁：左邊選範圍、寫補充說明、複製指令；右邊是整理記錄列表" width="900">
</p>

整理記錄只存在這台電腦（`~/.engram/local/tidy/`），不會同步，90 天後自動清除；在記錄頁可以手動刪除。

安全設計：

- **先提建議、你決定才動手**。`/engram:tidy` 只讀取記憶、建立整理記錄（技能只預先允許這些指令），寫入要等你在記憶整理頁決定、貼上 `/engram:tidy-apply` 之後；收件匣的 `/engram:inbox` 則是先提計畫、你同意才執行。每一筆寫入都附上 `engram undo <版本>`，可以逐項復原。
- **偵測到的金鑰不交給 Claude**。Claude 讀記憶時，疑似金鑰已在這台電腦上換成「‹已遮蔽›」。Engram 也不接受含疑似金鑰的寫入，Claude 會改成只記存放位置。
- **「不是金鑰」由你本人確認**。被誤判的值，請在你自己的終端機執行 `engram not-secret`（在 Claude Code 裡執行會被拒絕）。確認過的值只存雜湊、同步到所有電腦；標錯時用 `engram not-secret --list` 查看、`--remove` 撤銷。
- **讀取之後被改過就不覆蓋**。另一台電腦剛同步過來、或你在介面改過，寫入會被拒絕，Claude 會重新讀取再判斷。

### 對話回顧：拿對話紀錄驗證記憶

記憶寫錯了，或專案改了做法卻沒更新，Claude 還是會一直讀到、一直相信。Anthropic 的記憶研究發現，回頭拿原始的對話紀錄當證據驗證記憶，才修得回來（他們稱為 dreaming）。對話回顧就是做這件事。

<p align="center">
  <img src="assets/screenshots/dream.png" alt="對話回顧的整理記錄：每一項附上對話原文當證據，紅線表示與記憶不符、綠線表示證實" width="900">
</p>

1. **開始**：在專案資料夾開 Claude Code，輸入 `/engram:dream`（或在「記憶整理」頁選專案、整理方式選「對照對話紀錄」，複製指令）。可以加上補充說明，例如「重點看部署相關的記憶」。
2. **Claude 分析**：Engram 把這台電腦上這個專案還沒回顧的對話轉成精簡的文字（疑似金鑰先遮蔽），預設每次 20 個、由舊到新（可用 `--sessions` 調整，上限 100）；每一份對話文字（很長的對話會切成幾份）交給一個分析用的子代理，拿對話當證據檢查每一筆記憶：
   | 發現 | 建議 |
   | --- | --- |
   | 對話證實記憶仍然正確 | 「確認仍正確」：只在記憶記下驗證日期（證據裡最新的對話日期），內容不變。只用在容易過時、或超過 30 天沒確認的記憶，其他被證實的不會列出來 |
   | 記憶的說法已經改變（指令、路徑、決定） | 改寫成現況，舊的說法用一句話留下日期 |
   | 記憶裡的待辦、狀態已經過了 | 改寫，或整筆封存 |
   | 記憶寫得很肯定，對話裡其實只是推測 | 改成實際的確定程度 |
   | 對話裡有值得記、卻還沒記下的事 | 新增（會先查有沒有相近的記憶） |
   | 兩個對話的說法互相矛盾 | 兩種說法並列、標出日期，請你判斷 |
   | 對話比記憶的最後修改還舊，說法又不同 | 不改記憶（記憶多半是之後才更新的），在摘要提一句請你確認 |
3. **逐項決定**：Claude 給你一個網址，在記憶整理頁逐項決定，和一般的記憶整理相同；每一項都附對話的原文引句與日期（紅線表示與記憶不符，綠線表示證實）。
4. **執行**：按「產生執行指令」，把 `/engram:tidy-apply <id>` 貼回 Claude Code。

<p align="center">
  <img src="assets/screenshots/dream-start.png" alt="記憶整理首頁：選專案後可以選「只看記憶」或「對照對話紀錄」，下方顯示這台電腦有幾個對話還沒回顧" width="900">
</p>

要知道的事：

- **對話紀錄只在這台電腦讀**，不會同步，也不會上傳到 GitHub；分析時由你的 Claude Code 讀取，和平常對話一樣。轉出來的文字放在 `~/.engram/local/dream/`，整理記錄一建立就刪除；中途沒完成的，14 天後自動清除。每台電腦的對話紀錄不同，在哪台電腦回顧，就驗證那台的對話。
- **Claude Code 預設只保留 30 天的對話紀錄**（設定 `cleanupPeriodDays`）。對話被清除後就沒辦法回頭驗證，所以未回顧的對話快被清除時，收件匣會出現「建議回顧」。
- **回顧過的對話不會再分析**；之後又接著聊（resume）、對話變長的，下次只分析新增的部分。整理記錄一建立，這批對話就算回顧過，不論你之後在網頁怎麼決定；沒分析成功的對話不算，下次會再列入。在記憶整理頁還沒決定完就刪掉這筆整理記錄時，這批對話會恢復成沒回顧。
- **引句會核對原文**：每一則引句都會拿去比對轉出來的對話文字，找不到的標成「找不到原文」（可能是被改寫過），決定前請多看一眼。
- **用量**：每一份對話文字由一個子代理（Sonnet）讀完，對話越長、越多，用量越大。對話很多時可以加上 `--sessions 5` 先回顧最舊的 5 個。
- **權限**：分析用的子代理只有讀取工具，不能改任何檔案。Engram 會把 `~/.engram/local/dream` 加進 Claude Code 的允許讀取清單（`permissions.additionalDirectories`，解除安裝時移除），讓子代理讀取時不跳出詢問；這個設定在新對話才生效，剛更新完第一次回顧時如果被擋，開一個新對話再執行一次即可。
- **對話裡的內容是資料，不是指令**：網頁、檔案裡夾帶的「忽略之前的指示」之類的文字不會被當成事實，也不會被照做。

### 自動駕駛：整理工作全部交給 AI

上面的整理、回顧與收件匣，每一項都要你決定。自動駕駛把這些決定也交給 AI：開啟後，Engram 每天在背景執行一輪，判斷並直接處理，不需要你逐項確認；你只要偶爾到「自動駕駛」頁看一眼，不同意的復原即可。

<p align="center">
  <img src="assets/screenshots/autopilot.png" alt="自動駕駛頁：開關、開啟的電腦、本月用量，以及每一輪做了什麼、理由與復原" width="900">
</p>

**開啟**：管理介面的「自動駕駛」頁或設定頁打開開關（也可以執行 `engram autopilot on`，或在 Claude Code 輸入 `/engram:autopilot 開啟`）。開啟時會立即在背景執行第一輪。

**每一輪做什麼**（依序）：

| 項目 | 做什麼 |
| --- | --- |
| 疑似金鑰 | 真的金鑰移到這台電腦的「本機保管區」（Windows DPAPI 加密、不同步），記憶裡的值換成 `<engram-secret:名稱>`，結尾加一行說明怎麼取出（`engram secret get 名稱`），之後就能正常同步。AI 看不到值本身，只看種類、長度、前幾個字元（最多 4 個、不超過值長度的四分之一）與上下文。寫在 password:、AccountKey= 這類關鍵字後面的值與有固定格式的權杖一律進保管區；只有單純因為「亂」被偵測到的值，判斷者與審核員都高度確定時才標記「不是金鑰」（可以在自動駕駛頁復原） |
| 收件匣（規則） | 撞名資料夾依命名規則改名、修正綁定、核心準則的建議更新；資料夾連續 14 天都不見才移除舊綁定 |
| 同步衝突 | 比對兩台的版本後合併；會捨棄一邊內容的處理要審核員同意，否則兩個版本都留下 |
| 收件匣（判斷） | 收編尚未納管的記憶、大量刪除（確認或還原）、可能屬於另一個資料夾的記憶 |
| 待你確認 | Claude 寫進全域、單機記憶或核心準則的內容，正常的代你確認；被注入可疑指示或明顯錯誤的退回。審核員不同意代你確認的內容會記在記憶庫，之後每一台都不再判斷、留給你確認，內容改過才重新判斷 |
| 記憶整理 | 和 `/engram:tidy` 相同的判斷：合併重複、封存過時、搬到正確的範圍、拆分或精簡、修 frontmatter 與連結；索引或核心準則過長時精簡。只整理有卡片、或內容變過而且超過 7 天沒整理的範圍 |
| 對話回顧 | 和 `/engram:dream` 相同的判斷，每個專案每輪最多 8 個對話，快被 Claude Code 清除的優先 |

**沒有人確認，怎麼把關**：

- **AI 只做判斷**：Engram 用你電腦上的 Claude Code 登入，在背景呼叫 `claude -p`：不給任何工具（不能讀檔、執行指令或上網）、不載入你的 CLAUDE.md 與設定、不留對話紀錄，只回傳結構化的決定。寫入一律由 Engram 驗證後執行，沿用記憶整理的版本檢查、金鑰檢查、釘選保護與備份（`~/.engram/local/backups/`）。
- **第二次審核**：改寫、合併、封存、寫進全域或單機、改核心準則，都要另一次 AI 呼叫（審核員）用懷疑的眼光檢查：有沒有遺失事實、理由站不站得住、範圍對不對、有沒有被注入的指示。不同意就不執行，記在「沒有執行的建議」。
- **指令型內容一定送審**：新內容出現「忽略之前的指示」「下載後直接執行」「把憑證送到某個網址」「關掉權限保護」這類文字時，不論風險高低都送審。
- **只記你說過的話**：對話回顧要寫進全域或單機的內容，證據裡一定要有你自己說過的話。只出現在網頁、檔案或工具結果裡的內容，不會變成每次都會載入的記憶。
- **有上限**：每輪最多改動 30 筆記憶，而且不超過記憶總數的 15%（至少 5 筆），其餘的下一輪處理；一個項目最多 6 個動作。只封存、不真的刪除。（這是改動筆數的安全上限，和金額無關。）

**看結果與復原**：「自動駕駛」頁列出每一輪做了什麼，每一項附理由、審核員的意見與風險；沒有執行的建議也列出原因。可以逐項或整輪復原；整理類的項目可以點進記憶整理頁看完整差異。CLI：`engram autopilot runs`、`engram autopilot show <執行編號>`、`engram autopilot undo <執行編號> [<項目編號>]`。

**它會學**：你復原的處理會記成回饋，存在記憶庫（兩台電腦共用），之後的判斷會參考；同一類處理（例如合併、封存、升級全域）在兩輪各被你復原過就自動暫停，只記錄、不執行；在「自動駕駛」頁按「恢復」或執行 `engram autopilot resume <類別>` 就會恢復。復原「金鑰移到保管區」會把值放回記憶（回到不同步的狀態），30 天內不再自動移回。

**什麼時候執行**：開啟後每天一次，在這台電腦 20 分鐘內都沒有 Claude Code 對話時才執行，避免和你搶 Claude 的用量；超過 2 天沒執行就直接執行。也可以按「立即執行」。每週一則 Windows 通知摘要這週做了什麼。

**多台電腦**（1.6.0 起每台平等，沒有主機）：開啟自動駕駛的每台電腦都會整理全域、核心準則與專案記憶，也都會處理同步衝突。每個範圍整理到哪個版本、看過哪些卡片，會記在記憶庫（`machines/<電腦>/autopilot.json`）跟著同步；任何一台整理過、內容也沒再變的範圍（以記憶內容判斷，不看檔案時間），其他台就跳過，不會重複花用額度。每一輪開始前先同步；沒有同步成功（例如離線、暫停了同步）時，這一輪只處理這台自己的部分（單機記憶、金鑰、大量刪除的卡片、對話回顧），共用記憶的整理、同步衝突與待你確認下一輪再處理。兩台剛好同時改到同一筆時，同步會產生衝突，下一輪再合併，不會遺失內容。單機記憶只由自己那台整理；金鑰、待你確認與對話回顧也各台處理自己的（對話紀錄只在那台電腦）。所有電腦都要更新到 1.6.0：還在 1.5.0 的電腦看不到其他電腦的整理紀錄，可能重複整理同一批記憶。

**用量**：用你的 Claude 訂閱時不另外計費，但會消耗額度。頁面上的金額是 API 牌價的換算，用來設上限：每台每月預設約當 US$200；在「自動駕駛」頁可以選常用金額（50、100、200、500）或選「自訂金額」自己輸入 1～1000，也可以執行 `engram autopilot budget <美元>`。沒有每輪的金額上限，一輪可以用到本月剩下的全部（每次呼叫最多約當 US$3，避免單次失控）；本月用完就停，下個月再繼續，碰到 Claude 的用量上限也會停止、下一輪再繼續。每次呼叫的固定開銷約 4 千 token（不載入你的設定）。

**本機保管區**：`engram secret list` 列出這台電腦保管的項目，`engram secret get <名稱>` 取出值（Claude Code 需要時也會照記憶裡寫的指令取出）。保管區在 `~/.engram/local/secrets/`，只有這台電腦的這個 Windows 使用者解得開，不會同步；另一台電腦需要時，請在那台另外存一份。

> 剛更新 Engram、已經開著的對話看不到這些指令時，執行 `/reload-plugins` 或開一個新對話。Claude Code 第一次詢問是否允許執行 `engram` 指令時，按允許即可。

**開關面板**

| 方式 | 說明 |
| --- | --- |
| 底部的「◆ 憶跡 · 讀取 N」 | 在 Claude Code 底部右側，點一下開關面板。數字是這次對話讀取或搜尋到的記憶數（還沒有時只顯示「◆ 憶跡」）。滑鼠點擊只在全螢幕版面有效（見下方） |
| `/engram-memories` | 在 Claude Code 輸入，任何模式都能用 |
| 自動開啟 | 全螢幕版面、終端機至少 144 欄寬時，新對話會自動開啟。關掉一次之後就不再自動開啟，用上面兩種方式打開即恢復 |

**全螢幕版面**是 Claude Code 預設的畫面（不是把終端機視窗最大化）：面板停靠在對話右側，可以用滑鼠點按鈕與每一列。設了環境變數 `CLAUDE_CODE_NO_FLICKER=0`、或在 tmux 裡執行時，Claude Code 改用一般畫面：面板顯示在輸入框上方，收不到滑鼠點擊，請用指令與鍵盤操作。

**看懂面板**

| 區塊或標記 | 意思 |
| --- | --- |
| 開場載入 | 對話一開始就放進 Claude 腦袋的檔案。`├ └ │` 連接線表示誰用 `@` 匯入了誰，右側是估計的 token 數，標題列右側是合計。送出第一個訊息前這裡是空的；對話被壓縮後標題會變成「壓縮後重新載入（第 N 回合）」 |
| 對話中讀取 | 對話途中 Claude 讀取或搜尋到的記憶，以及 Claude 讀到相關檔案時自動載入的指示檔（例如子資料夾的 CLAUDE.md、符合條件的規則檔）。`#3` 是第 3 回合，● 是這一回合新讀到的，`×2` 是讀了兩次，「子代理」表示由子代理讀取。對話被壓縮後，壓縮前讀取的記憶會調暗，上方標出「內容已整理成摘要」 |
| 全文 | 整份內容在對話裡：CLAUDE.md、CORE.md，以及 Claude 讀取過的記憶 |
| 標題 | 只有標題與一句話說明。開場載入的 INDEX.md、MEMORY.md 都是索引：Claude 知道有這些記憶，但還沒讀內容。「標題 18 則」表示這個索引列了 18 則記憶 |
| 摘要 | `engram search`（或在記憶資料夾裡搜尋）結果裡的說明與一小段內文，沒有讀全文 |
| ⚠ 只看得到前 N 則 | MEMORY.md 超過 Claude Code 的載入上限（前 200 行或 25KB），後面的記憶 Claude 看不到。用收件匣或 `/engram:tidy` 整理 |
| 範圍 | 核心、全域、單機、專案，以及「指示」（CLAUDE.md 與 `.claude/rules`） |

**操作**：點一列看記憶內容，以及它是怎麼、什麼時候進到對話的；`b` 返回、`f` 依範圍篩選、`l` 切換中文與 English（選擇會記住；沒切換過時跟著 Claude Code 的 language 設定，沒設定時是英文）。用鍵盤操作時先按 Ctrl+X Tab 讓面板取得鍵盤，Tab 移動、Enter 選擇，Esc 回到輸入框。

**限制**

- 需要支援外掛畫面（mods）的 Claude Code；實測 2.1.307 至 2.1.309 可用，更早的版本未測試。
- 偵測的是 Read 工具、`cat`／`Get-Content` 這類讀檔指令、`engram search`／`engram memory show`，以及在記憶資料夾裡的搜尋；用其他方式（例如 `grep`、`Select-String` 或寫程式）讀取的不會列出。面板也不判斷回答「實際引用」了哪一則。
- 壓縮的事件被其他外掛略過時，面板改用估計的 token 驟降判斷，可能晚一回合才標出「壓縮後重新載入」，也可能把 `/rewind` 這類大幅縮減對話的操作當成壓縮。
- 面板只在本機讀取，不呼叫 AI，也不送出任何資料。

## 6. 收件匣與健康卡片

Engram 每天檢查一次記憶的狀況，有需要你決定的事就放進收件匣。大多數卡片都有一個主要按鈕可以一鍵處理，也可以選「七天後提醒」或「忽略」。Claude 不會主動提起收件匣，除非你問它。

| 嚴重度 | 卡片 | 意思 | 建議 |
| --- | --- | --- | --- |
| 高 | 索引超過載入上限 | 某專案的記憶索引超過 200 行或 25 KB，後面的不會被 Claude 看到 | 合併或封存舊的記憶 |
| 高 | 疑似含有金鑰 | 這筆記憶不會被同步 | 按「移除金鑰」，再按「遮蔽並恢復同步」：記憶裡的金鑰在本機換成「‹已遮蔽›」後恢復同步；如果不是金鑰，選「這不是金鑰」 |
| 高 | 衝突待處理 | 兩台電腦改了同一筆記憶的同一段 | 見第 7 節 |
| 高 | 偵測到大量刪除 | 一次刪掉某專案一半以上（至少 3 筆）的記憶，Engram 先扣住、沒有同步 | 不是你刻意的，就按「還原」 |
| 高／中 | 記憶連結失效／資料夾撞名 | 某個專案的記憶沒有正確接到記憶庫，或兩個資料夾撞名 | 連結失效：按「重新建立連結」；撞名：見第 8 節 |
| 中 | 內容相同的記憶／可能重複 | 兩筆以上記憶內容相同，或名稱、說明非常像 | 按「合併」，或「並排比對與合併」 |
| 中 | 看起來只適用這台電腦 | 內容提到這台電腦的安裝位置或環境 | 改為單機記憶 |
| 中 | 可能屬於另一個資料夾 | 撞名期間寫錯地方的記憶 | 移到正確的資料夾 |
| 中／低 | 每次對話都會載入的內容偏多 | 核心準則加全域、單機索引超過 20 KB（超過 25 KB 為中） | 「交給 Claude 精簡」，或封存很少用到的全域記憶 |
| 低 | 可能適用所有專案 | 例如你的偏好卻只存在一個專案裡 | 升級為全域 |
| 低 | 可能已過時 | 很久沒更新、專案也很久沒開 | 封存（可以還原） |
| 低 | 建議回顧對話 | 專案有還沒回顧的對話，而且最早的一個 7 天內會被 Claude Code 清除，或專案裡容易過時的記憶（專案進度、寫著「待辦」「尚未」的）超過 30 天沒確認 | 「交給 Claude 回顧」，見第 3 節「對話回顧」 |
| 低 | 連結斷了 | 記憶裡的 `[[名稱]]` 指向已經合併或封存的記憶 | 改連到合併後的記憶，或拿掉連結只留文字 |
| 低 | 很少用到／只在一個專案用到 | 全域記憶近 90 天沒有被打開過全文（索引那一行每次都會載入，不算；最後修改在 60 天內的不提醒），或只在一個專案被打開過（至少 3 次、分布在 2 天以上）。釘選的不提醒；讀取統計要累積 60 天以上才判斷 | 封存，或搬到那個專案；通用的做法維持全域即可 |
| 低 | 待你確認的內容 | Claude 自己新增或修改了全域記憶、單機記憶或核心準則 | 「檢視與確認」，見下方 |
| 低 | 核心準則有建議更新 | Engram 新版建議在「記憶寫入協定」加入幾句話 | 到「核心準則」頁看過後一鍵加入，見第 9 節 |

需要讀內容才能判斷的卡片有「交給 Claude」按鈕，會給你一個指令，貼到任一個 Claude Code 對話即可。

### 待你確認：Claude 寫入每次都會載入的內容

全域記憶、這台電腦的單機記憶與核心準則，在每個專案的每次對話都會被讀到；一筆寫錯（或被對話裡夾帶的指示誘導寫入）的記憶，影響會擴散到所有專案。所以 Claude 自己寫入這些內容時，收件匣會出現「待你確認」：

<p align="center">
  <img src="assets/screenshots/review.png" alt="待你確認的對話框：每一筆顯示修改前後的差異或新增的全文，可以確認、編輯或退回" width="900">
</p>

- 修改的顯示前後差異，新增的顯示全文。可以「確認」「編輯」，或「退回確認過的版本」（新增的則是封存，可以還原）。
- 你在管理介面編輯、合併、搬移的，在記憶整理頁採用建議後執行的，用 `/engram:save` 同意寫入的，都算你確認過，不會再問。選「依備註調整」的項目由 Claude 改寫，內容你還沒看過，仍會列為待確認。
- 只改一個欄位的動作（記下驗證日期、釘選、改連結、遮蔽金鑰）沿用原本的狀態：原本確認過就仍算確認過，原本待確認就仍待確認。收件匣的一鍵「升級為全域」也會請你確認內容。
- 更新到 1.4.0 後第一次執行時，現有內容當成起點（算確認過），之後的寫入才會問。第二台電腦更新時只把自己的單機記憶當成起點，不會把另一台電腦還沒確認的內容一起標成確認過。
- 任何一台電腦確認過都算。只是提醒，不會擋住寫入；不需要時可以在設定頁的「健康檢查」關閉。

### 讀取統計

Engram 從這台電腦的對話紀錄算出每筆記憶被讀了幾次（同一個對話同一天只算一次），在記憶庫的記憶詳情顯示「近 90 天被讀了幾次、最後一次是哪天、在哪些專案」。統計只在本機計算，每天把讀取次數的摘要同步一次，所以兩台電腦的次數會合計。

- 全域與單機索引放不下時（記憶很多），先列釘選的，再列最近 14 天新增或修改的，然後是讀取次數多的；其餘可以用 `engram search` 找到。讀取次數要等所有電腦都更新到 1.4.0 才用來排序，免得新舊版本把索引改來改去。
- 統計累積 60 天以上之後，很少用到或只在一個專案用到的全域記憶會出現在收件匣。
- 記憶詳情也會列出這筆記憶 `[[連到]]` 哪些記憶、被哪些記憶連結，以及對話回顧最後一次確認仍正確的日期。

## 7. 衝突怎麼處理

同一個人很少同時在兩台電腦改同一筆記憶，所以衝突應該很少見。真的發生時：

1. Engram 會自動合併能合併的部分，例如兩邊改了不同段落。
2. 合併不了的，這台電腦保留自己的版本，另一台的版本放進衝突區。兩台電腦都看得到這張衝突卡。
3. 按衝突卡上的「比對並決定」，會並排顯示兩個版本與共同的原始版本。可以選「保留這台的版本」「改用〈另一台〉的版本」「兩者都保留」（另一台的版本另存成 `-2.md`），或直接在左欄編輯後按「儲存左邊的合併結果」。
4. 兩邊各自加了不同的內容、不想自己逐段搬時，按「交給 Claude 合併」，Claude 會說明兩邊各改了什麼，寫出合併版本讓你確認。

Claude 讀到的檔案裡永遠不會出現衝突標記。

## 8. 資料夾撞名

Claude Code 會把資料夾路徑換成一個內部名稱，中文字、空白、底線、點等符號都會變成連字號。所以同一層、字數相同的中文資料夾（例如「甲方專案」和「乙方專案」），或只差在符號的英文資料夾（例如 `my_proj` 和 `my proj`），會共用同一個內部名稱，記憶和對話紀錄就混在一起。這是 Claude Code 本身的限制。

Engram 的處理：

| 做法 | 效果 |
| --- | --- |
| 自動偵測撞名 | 撞名的資料夾不會被錯誤地接在一起 |
| 改用專案設定檔指定記憶位置 | 記憶可以分開；但只在從該資料夾本身啟動 Claude Code 時有效，對話紀錄仍會混在一起 |
| 事後才出現的撞名 | 在對話開頭警告 Claude 不要引用、也不要寫入記憶 |
| **依命名規則改名（根本解法）** | 在原名後面加 4 碼代號，例如「照片優化」改成「照片優化-66ca」。中文名稱照樣看得到，在 Claude Code 裡就不再撞名 |

改名時會一併重新綁定、更新這台電腦寫的記憶裡的舊路徑。為了不影響其他程式，下列資料夾不會自動改名：30 分鐘內有對話或檔案修改、裡面還有其他專案、有 Python 虛擬環境或 git worktree、在 OneDrive 底下，或 Claude Code 為它記了 MCP 伺服器、允許的工具。

在「設定 › 撞名的資料夾」選擇處理方式：

| 選項 | 做法 |
| --- | --- |
| 在收件匣詢問（預設） | 撞名卡片列出建議的新名稱，按「依命名規則改名」才改 |
| 自動改名 | 常駐程式每小時檢查一次，改完發通知 |
| 關閉 | 不改名；記憶仍用設定檔分開，對話紀錄會混在一起 |

想還原：在「裝置與同步」的變更紀錄找到那一筆按「復原」，或執行 `engram collisions undo <id>`（`engram collisions` 會列出最近一次的 id）。

> **改名前要知道**：Claude Code 的對話紀錄也依內部名稱存放。改名後在新資料夾開 Claude Code，`/resume` 清單不會有改名前的對話（它們仍保存在 `~/.claude/projects/` 底下）。記憶不受影響。還想接續的舊對話，請在改名前先完成。

## 9. 核心準則

核心準則（`CORE.md`）是每次對話都會載入的一份文件，所有專案、所有電腦共用。內容包括你的身分與偏好、工作環境清單，以及教 Claude 怎麼把記憶寫到正確範圍的「記憶寫入協定」。

- 在管理介面的「核心準則」頁編輯，或按「請 Claude 精簡」交給 `/engram:tidy` 整理。
- 「載入預算」顯示核心準則與兩份索引合計的行數與大小。這一層每個專案、每次對話都會載入，建議維持在 20 KB 以內。
- **建議更新**：Engram 1.4.0 依 Anthropic 的記憶研究調整了範本的「記憶寫入協定」：說明記憶是為了什麼（「記下之後用得到、而且不寫下來就會遺失的事」，讓 Claude 自己判斷，而不是規定死規則），以及寫下規則時註明怎麼確認的（實測、查文件或推測）。核心準則是你的檔案，Engram 不會自己改；找得到原本範本的位置時，「核心準則」頁會列出建議，看過覺得合適再按「加入」，之後可以從變更紀錄復原。
- 原本 `~/.claude/CLAUDE.md` 裡的工作準則不會被搬走。希望每台電腦的工作準則一致時：在「匯入既有記憶」頁套用匯入之後，會出現「選用：讓所有電腦共用你的工作準則」，按「同步工作準則」：先預覽搬移後的內容，同意後才搬進記憶庫；之後可以按「改回各台電腦自己的版本」逐位元還原。

## 10. 暫停、復原與移除

| 想做的事 | 怎麼做 |
| --- | --- |
| 暫時停用 | 設定頁的「暫停 Engram」。暫停期間不同步、不自動接上新專案；Claude 照常記憶，恢復後一起處理 |
| 復原某個整理動作 | 動作完成時的通知可以直接按「復原」；記憶整理的項目在整理記錄頁按「復原這一項」；之後也可以到「裝置與同步」的變更紀錄找到那一筆 |
| 還原某次匯入 | 匯入頁的「還原到匯入前」，或 `engram import undo <還原點>`。匯入後才改過或新增的記憶會保留最新版，被取代的舊版另存成 `.pre-rollback` |
| 某個專案不要用 Engram | 在該資料夾執行 `engram unbind`。記憶會複製回 Claude Code 原本的資料夾 |
| 新專案先問我再接上 | 設定頁的「自動綁定專案資料夾」改成「每次都詢問」或「關閉」 |
| 整個移除 | `engram uninstall`：先列出計畫，同意後逐項還原到安裝前。**預設保留記憶庫**，之後重新安裝直接沿用；加上 `--purge` 才會連本機的記憶庫一起刪除（GitHub 上的 repo 不受影響） |

## 11. 更新

1. 取得新版程式：
   - 用 git 安裝的：在 Engram 資料夾執行 `git pull`
   - 用 ZIP 安裝的：下載新版本的 ZIP，解壓縮覆蓋原本的 Engram 資料夾（ZIP 以版本號區分，同一版本重複解壓不會更新）
2. 執行 `engram update`。它會部署新版、重新啟動常駐程式。
3. 已經開著的 Claude Code 對話執行 `/reload-plugins`；新開的對話會直接使用新版。

新版有問題時，`engram update --rollback` 切回上一版。Engram 資料夾搬到別處的話，用 `engram update --from "<新位置>\app"`；更新成功後會記住新位置，之後直接 `engram update` 即可。

## 12. 指令速查

| 指令 | 做什麼 |
| --- | --- |
| `engram status` | 這台電腦、目前資料夾的綁定與同步狀態 |
| `engram ui` | 開啟管理介面 |
| `engram sync` | 立即同步 |
| `engram doctor` | 逐項檢查環境；加上 `--probe` 另外確認這一版 Claude Code 的行為與 Engram 的假設一致（會使用你的 Claude 額度） |
| `engram search <關鍵字>` | 搜尋所有範圍的記憶 |
| `engram projects` | 列出所有專案 |
| `engram bind` ／ `engram unbind` | 把目前資料夾綁定到專案／解除綁定 |
| `engram import plan` | 產生匯入計畫（`apply --yes` 套用、`undo <還原點>` 還原） |
| `engram collisions` | 列出撞名的資料夾與建議的新名稱（`apply` 改名、`undo <id>` 整批還原） |
| `engram undo <版本>` | 復原一次寫入、移動、封存、合併或衝突處理 |
| `engram tidy list` | 列出記憶整理的記錄（`show <id>` 看內容；`create`、`apply`、`done` 由 `/engram:tidy` 與 `/engram:tidy-apply` 使用） |
| `engram dream status` | 這台電腦上目前專案有幾個對話還沒回顧、最早的何時會被清除（`prepare`、`done`、`list` 由 `/engram:dream` 使用） |
| `engram autopilot` | 自動駕駛的狀態（`on`、`off` 開關；`run` 立即執行一輪；`runs`、`show <編號>` 看紀錄；`undo <編號> [<項目>]` 復原；`resume <類別>` 恢復暫停的處理；`budget <美元>` 每月上限） |
| `engram secret list` | 本機保管區的項目（`get <名稱>` 取出值；`check` 檢查每一筆解不解得開；`delete <名稱>` 移除解不開的項目） |
| `engram not-secret` | 把被誤判為金鑰的值記入「不是金鑰」清單（只能在你自己的終端機執行） |
| `engram update` | 部署新版本（`--rollback` 切回上一版） |
| `engram uninstall` | 依安裝紀錄還原到安裝前（`--dry-run` 只列計畫、`--purge` 連本機記憶庫一起刪除） |
| `engram help <指令>` | 查看某個指令的完整用法 |

Claude Code 裡的 `/engram:inbox`、`/engram:tidy`、`/engram:tidy-apply`、`/engram:dream`、`/engram:autopilot`、`/engram:save`、`/engram:recall` 見第 3 節，記憶面板的 `/engram-memories` 見第 4 節。
