# 快速開始

約 15 分鐘，讓你在幾台電腦上共用同一套 Claude Code 記憶。整個安裝只要執行一個檔案，其餘步驟都會先列出來、等你同意才進行。

> 不想自己操作？把 [AI 幫你快速安裝.md](../AI%20幫你快速安裝.md) 開頭那段話貼給 Claude Code，讓它代你完成。

## 1. 開始之前

| 需要 | 說明 |
| --- | --- |
| Windows 11 | 需要內建的 winget，安裝程式會用它補齊缺少的工具 |
| Claude Code | 用官方安裝程式安裝，並登入過一次。安裝程式不會替你安裝 Claude Code |
| GitHub 帳號 | 記憶庫會放在你帳號底下的私人 repo。還沒有帳號的話，先到 [github.com](https://github.com) 註冊 |
| Node.js、Git、GitHub CLI | 不用自己裝，缺少的話安裝程式會自動安裝。已經裝了但 Node.js 低於 22 時，安裝程式會請你先升級 |

> **先確認公司規定。** 記憶裡可能有客戶與專案細節。如果公司不允許把工作資料放在個人 GitHub，請改用公司 GitHub 組織底下的私人 repo（先請管理員建立一個空的 repo，安裝時加上 `--remote <repo 網址>`，見[第 7 節](#7-自己下指令安裝)），或只在單機使用（`--local`）。

## 2. 取得 Engram

擇一：

- **用 git（建議，之後更新最方便）**：
  ```powershell
  git clone https://github.com/Sen-CaPoo/engram.git "$HOME\engram"
  ```
- **下載 ZIP**：在 GitHub 頁面點 **Code → Download ZIP**，解壓縮到你方便的位置，例如 `C:\Users\你的名字\engram`。

**請保留這個資料夾**，之後更新會用到。

## 3. 雙擊 `setup.cmd`

它會依序做四件事，每一步都會顯示在畫面上：

| 步驟 | 做什麼 |
| --- | --- |
| 1/4 檢查工具 | 缺少 Node.js、Git 或 GitHub CLI 時，用 winget 自動安裝 |
| 2/4 登入 GitHub | 還沒登入的話，會開瀏覽器讓你登入一次 |
| 3/4 安裝 Engram | 先問這台電腦的名字（例如「公司電腦」），再列出安裝計畫，等你輸入 `y` 同意 |
| 4/4 開啟管理介面 | 瀏覽器開啟 `http://127.0.0.1:4777` |

安裝程式會自動判斷這是第一台還是之後的電腦：你的 GitHub 上還沒有 `engram-vault`，就建立一個私人 repo；已經有了，就接上它，並下載其他電腦已同步的記憶。

> **想先看看會做什麼？** 在終端機執行 `setup.cmd -DryRun -Label 公司電腦`。它只做檢查，不安裝也不修改任何東西。工具齊全而且已登入 GitHub 時，最後會印出正式執行時的安裝計畫；否則會列出還缺什麼。
>
> **出現 Windows 安全性警告？** 從網路下載的檔案第一次執行時，Windows 可能詢問是否執行，選「執行」即可。

**小技巧**：管理介面建議用 Edge 開啟，從選單選「應用程式 › 將此網站安裝為應用程式」，之後就能從開始功能表開啟。

## 4. 匯入既有記憶（第一次）

如果你已經用 Claude Code 一陣子，電腦裡會有舊的記憶。在管理介面的「匯入既有記憶」依序操作：

1. **產生計畫**：Engram 列出每筆記憶屬於哪個專案、建議的範圍與動作，重複的內容和較舊的版本會自動略過。這一步不寫入任何東西。
2. **檢查建議的範圍**：判斷原則只有一句——**換到另一台電腦還成立嗎？** 不成立的放「單機」；成立的話再問**換到別的專案還成立嗎？** 成立的放「全域」，不成立的放「專案」。
3. **開始演練**：在複本上完整跑一次匯入、驗證與還原，不碰真實檔案，約 20 秒。四項檢查都打勾後，「套用計畫」才能按。
4. **套用計畫**：完成後顯示還原點（例如 `engram-import-20261022-…`），之後隨時可以一鍵還原。原始記憶檔一律保留不刪。

## 5. 確認接上了

1. **開一個新的 Claude Code 對話**：在任何已匯入的專案資料夾開新對話，問 Claude「你有看到 Engram 的狀態嗎？」。它應該會回答類似「公司電腦 · 專案：xxx · 已綁定」。
2. **在終端機看狀態**：新開一個 PowerShell、命令提示字元或 Git Bash，執行：
   ```powershell
   engram status
   engram doctor
   ```
   `doctor` 會逐項檢查記憶連結、GitHub 連線、常駐程式與登入工作。如果剛匯入的專案正有對話開著，它的連結會在對話結束後自動接上，在那之前顯示 ✗ 是正常的。

## 6. 第二台電腦

步驟和第一台完全一樣：取得 Engram、雙擊 `setup.cmd`、取一個不同的名字（例如「家裡電腦」）。

- **git 專案**：只要 remote 相同，第一次在這台開 Claude Code 就會自動接上。
- **這台也有舊記憶**：一樣到「匯入既有記憶」匯入，和第一台相同的內容會自動略過。
- **不是 git 的資料夾**：會先成為新專案，可以在「專案」頁用「併入」和另一台的同一個專案合併。

## 7. 自己下指令安裝

不用 `setup.cmd`、想自己控制每一步時，先自行安裝 Node.js 22 以上、Git、GitHub CLI 並執行 `gh auth login`，再在 Engram 資料夾執行：

```powershell
node app/bin/engram.mjs install --label 公司電腦                  # 自動判斷第一台或之後的電腦
node app/bin/engram.mjs install --remote <網址> --label 公司電腦   # 指定記憶庫，例如公司組織的 repo
node app/bin/engram.mjs install --local --label 公司電腦           # 只在這台電腦使用，不同步
node app/bin/engram.mjs install --dry-run                         # 只列出計畫，不做任何改動
```

其他選項：`--no-cli`（不建立終端機的 `engram` 指令）、`--no-schedule`（不建立登入工作）、`--yes`（略過確認詢問）。

## 8. 安裝會改動哪些地方

| 位置 | 做什麼 |
| --- | --- |
| `%USERPROFILE%\.engram\` | 記憶庫、程式本體、本機狀態與備份 |
| `~/.claude/CLAUDE.md` | 在檔案末尾加一段兩行的 Engram 區塊，原本的內容不動；修改前先備份 |
| Claude Code 外掛 `engram` | 對話開始與結束時的 hooks、`/engram` 指令 |
| npm 全域指令 `engram` | 讓一般終端機也能輸入 `engram`；不想要的話安裝時加上 `--no-cli` |
| Windows 工作排程器 `\Engram\Agent` | 登入時在背景啟動 Engram，每 10 分鐘同步一次 |
| 匯入時綁定的專案資料夾 | `.claude\settings.local.json` 寫一行 `autoMemoryDirectory`；不是 git 的資料夾另外寫一個 `.claude\engram.json` 標記 |
| `~/.claude/settings.json` 與記憶資料夾 | 只在預設權限模式是 auto 或 bypassPermissions 時：原本的記憶資料夾備份後換成連結，並在 `additionalDirectories` 加入連結路徑 |

每一項都記在安裝紀錄裡。`engram uninstall` 會先列出移除計畫，同意後逐項還原，預設保留記憶庫。

> **建議：把 Claude Code 的預設權限模式設為 auto。** 不設也能用：從專案根目錄開 Claude Code 完全正常，只是從子資料夾開啟時用不到 Engram 的記憶。安裝計畫會提醒你目前的設定。
